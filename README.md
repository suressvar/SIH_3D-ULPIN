## Local startup with Docker

Requirements: Docker Desktop with a working Linux engine. These commands are PowerShell, from the repository root. Ports are bound to localhost. Compose credentials are local demonstration credentials only.

```powershell
Copy-Item .env.example .env
docker compose up -d db redis
docker compose build
docker compose run --rm -e DATABASE_URL=postgresql+psycopg://astra:astra_local@db:5432/astra api alembic -c alembic.ini upgrade head
docker compose run --rm -e DATABASE_URL=postgresql+psycopg://astra:astra_local@db:5432/astra api python -m app.seed
docker compose up -d api worker scheduler
```

Open [API documentation](http://localhost:8000/docs), [liveness](http://localhost:8000/health/live), [readiness](http://localhost:8000/health/ready) and [capabilities](http://localhost:8000/api/v1/capabilities). The frontend runs separately; see the phase-four run guide.

The API and worker use the restricted `astra_app` role. Migration, seed and membership commands use the local administrator credential. Do not run the application with a database superuser in production.

## Authentication

Set `SUPABASE_URL` to your actual Supabase project using asymmetric ES256 or RS256 signing keys. Sign users in through Supabase Auth (configure OAuth providers externally; password and access-token UI is available). No credential or token is generated by this prototype.

Provision an existing Supabase user's UUID with the administrator CLI:

```powershell
docker compose run --rm -e DATABASE_URL=postgresql+psycopg://astra:astra_local@db:5432/astra api python -m app.manage USER_UUID surveyor
```

Replace `USER_UUID` with the actual user's UUID. Supported roles: viewer, surveyor, officer, admin. Use the Supabase access token in Swagger's Authorize dialog as a bearer token. Do not use the publishable key as a user token. Roles come from the private membership table, not user-editable JWT metadata. A reviewer cannot approve their own submission.

Synthetic seed actors are inactive and cannot sign in. There is no demo authentication bypass.

## Python development

Python 3.12 is required. PostgreSQL with PostGIS and Redis can be provided by Compose while Python runs locally.

```powershell
py -3.12 -m venv .venv
.venv/Scripts/python.exe -m pip install -r backend/requirements.lock
.venv/Scripts/python.exe -m pip install --no-deps -e backend
.venv/Scripts/python.exe -m uvicorn app.main:app --reload
```

If Python 3.12 is installed at a different path, use that executable to create the environment. The repository's current local environment was created with the bundled Python 3.12 runtime.

Run Celery workers in Linux Docker, not native Windows. Celery Beat dispatches persisted jobs every five seconds. Run only one scheduler per deployment.

Without `TEST_DATABASE_URL`, database integration tests are explicitly skipped. To exercise actual PostGIS, use the dedicated database created by Compose:

```powershell
$env:TEST_DATABASE_URL = 'postgresql+psycopg://astra:astra_local@localhost:54329/astra_test'
.venv/Scripts/python.exe -m pytest backend/tests -q
Remove-Item Env:TEST_DATABASE_URL
```

The tests refuse database names other than `astra_test`. The schema is migrated; test records are enclosed in rolled-back transactions. Do not point tests at a shared database. GitHub Actions defines the same checks against a real PostGIS service; it has not been remotely run merely because the workflow file exists.

## Important limits

- The application models one trusted project team. It is not a multi-tenant national deployment.
- Only Polygon GeoJSON parcel imports are normalized now (1–100 features, at most 10,000 vertices per footprint). PDF/PNG/JPEG are stored as evidence based on file signatures; no extraction or malware scanning is claimed.
- No arbitrary CRS or height is guessed. Standard GeoJSON defaults to EPSG:4326; nonstandard projected data requires declared source CRS. A metric projected EPSG CRS in its area of use is required.
- Heights are explicit and reference-labelled. Vertical datum conversion is not implemented. Ellipsoidal, orthometric and local-reference heights must not be compared as if interchangeable.
- Validation is restricted to vertical prisms. Stacked floors sharing a face are not volume conflicts. It is not a generic solid, legal-title, cross-parcel, structural or gap validation system.
- Sources, geometry, rights, evidence, decisions and audit provenance are retained. Storage is outside the database transaction; failed registration can leave an unreferenced private object, so a future garbage collector is needed.
- Queued cancellation works. Running jobs cannot be cancelled safely in this phase. Interrupted work is failed, never silently completed.
- HTTPS must terminate at the deployment ingress. No cloud deployment, production security assessment, operational SLA or accuracy percentage is claimed.
